# Graph Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the islands-and-orbits hero map with an Obsidian-style graph of six domain hubs and fifteen works, driven by the weights and links in `data/map-areas.json`, on the homepage, the mini maps and the social card.

**Architecture:** The Python build emits hub positions (stable between builds) and each work's homes and links; a pure ESM module runs a seeded force simulation that both the canvas renderer and the Node social-card script import; the renderer keeps `MapView`'s options and methods so its callers barely change.

**Tech Stack:** Vanilla ES modules and canvas, esbuild bundle, `node --test`, Python 3.12 with numpy/umap/sentence-transformers via `uv run`, headless Chrome for the card.

**Spec:** `docs/superpowers/specs/2026-10-20-graph-map-design.md`

## Global Constraints

- No new dependency, in JavaScript or Python.
- Areas keep their spec order; colours are `--a0` to `--a5`; links and highlights use `--accent`; names in Plex Mono spaced capitals via `nameLines` and `spaced`; work labels in Plex Sans; markers circle/square/diamond for paper/project/role.
- A membership counts as a home at weight `0.2` or more. A work's `area` is the spec file's `area`, which must be one of its heaviest weights.
- Hubs never move between builds unless the set of area names changes.
- Determinism: same data, same box, same seed, same picture.
- Reduced motion: no settle animation, no idle drift, no live physics. Touch: no drag, `touch-action: pan-y` stays.
- Commit messages describe the change only; no attribution lines.

## Review Focus

1. A work in the spec file whose every weight is below 0.2 would have no home; the build must stop with the work's id, never emit it. (Task 1 guards it and the test asserts every work has a home.)
2. Hiding a kind with the legend can leave a hub with no visible work (hide Production systems: Document AI); the hub must still be drawn, with no spokes and no stray labels. (Task 3, verified in the preview.)
3. With reduced motion the rested graph must appear at once and the frame loop must stop; the mini map takes the same path. (Task 2's `settle` cools to `heat === 0`; Task 3 verifies the mini map draws once.)
4. The first build after an area is added, renamed or removed, or with no published map, must start from the raw centres without crashing and still align the picture. (Task 1 verifies by rebuilding with the published map moved aside.)
5. On a narrow plot the hubs' name boxes can overlap because plot units squash; the layout must nudge hubs apart deterministically. (Task 2 tests it; Task 3 verifies on the phone preset.)

### Task 2: The shared force layout

**Files:**
- Create: `src/graph-layout.js`
- Test: `tests/graph-layout.test.mjs`

**Interfaces:**
- Consumes: `map.json`'s `areas[]` (`x`, `y`, `size`) and `works[]` (`homes`, `links`).
- Produces: `createGraph(data, box, options) -> Graph`, with
  - `data`: `{areas, works}` as above.
  - `box`: `{x, y, w, h}` in px. `unit = Math.max(0.45, Math.min(1.25, Math.min(w, h) / 620))`.
  - `options`: `{seed = 7, hubBoxes = null}`; `hubBoxes[a] = {w, h}` is the name box size in px, used to nudge hubs apart.
  - `Graph.hubs: {x, y, r}[]` in px, `r = (6 + 1.2 * size) * Math.max(0.75, unit)`.
  - `Graph.nodes: {x, y, vx, vy, pinned}[]`, one per work.
  - `Graph.heat: number` in `[0, 1]`.
  - `Graph.start()`: puts every node at the weighted middle of its homes plus a seeded nudge of up to ±30·unit px, sets `heat = 1`.
  - `Graph.step()`: one iteration; returns the new `heat`. Does nothing at `heat === 0`.
  - `Graph.settle()`: calls `step()` until `heat === 0` (at most 600 steps); returns `nodes`.
  - `Graph.pin(w, x, y)` / `Graph.release(w)`: fixes a node to a point or frees it; `pin` sets `heat` to at least `0.5`.
  - `Graph.reheat(h = 0.5)`.

- [ ] **Step 3: Implement `createGraph` in `src/graph-layout.js`**

A pure module: no DOM, no imports. Use `mulberry(seed)` (copy the function from `src/map.js`, then have `map.js` import it from here). Forces per step, with `u = unit`:
- Repulsion between every pair: `k / (d² + 60)` along the pair, with `k = 12000·u²` when either is a hub, `9000·u²` between works, and hubs never move from forces.
- Home spring for each `[a, w]` of a work: rest `(84 + 70·(1 − w))·u`, stiffness `0.03`.
- Link spring: rest `170·u`, stiffness `0.005`.
- Pull toward the box centre: `0.004` of the offset.
- Integration as in the mockup: `v = (v + f·0.5·heat)·0.6`, then clamp to the box inset by `12 + 20·u` px; pinned nodes keep their point and zero velocity.
- `heat` falls by `0.006` per step to a floor of 0; `settle` stops at 0 or 600 steps.
- Hub nudge when `hubBoxes` is given: before anything else, up to 50 passes pushing any two hubs apart horizontally until their boxes clear by 8 px (`|dx| ≥ (w₁ + w₂)/2 + 8` or `|dy| ≥ (h₁ + h₂)/2 + 8`), then clamp hubs to the box with half a box's margin.
